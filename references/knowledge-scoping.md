# Разделение знаний: проектные скилы vs глобальная база

> Справочно (методика исходной системы для multi-репо сценариев). Наш воркспейс —
> один: база `memory/records/` + скиллы `.kimi-code/skills/`; проектных `.agents/skills`
> в репо не заводим; для дерева проекта — `project-search` (справочник
> `project-search.md`). Куда класть у нас — «Правило „куда класть“» в
> `references/skills-management/SKILL.md`.

Этот скил — канон ответа на вопрос «куда сохраняется знание» (исходная
система). Создан по итогам аудита проектных скилов ROBRA (2026-09-16).

## Таксономия знаний

| Категория | Определение | Где хранится |
|---|---|---|
| **Проектное** | Знания, нужные для работы с конкретным продуктом/репозиторием: архитектура, схемы, правила кода, стенды, справочники | **Проектный скил** в дереве проекта (`.agents/skills/`) |
| **Общее переиспользуемое** | Принципы, применимые в нескольких проектах: ClickHouse, Confluence, Grafana, общие библиотеки | **Глобальный скил** (`entity-*`, общие методики); в проектном скиле — только самодостаточная проектная часть |
| **Персональное** | Способы доступа в корпсеть (прокси/VPN/джамп-хосты/SSH-алиасы), личные токены и логины, личная методология организации памяти | **Только глобально**. В дерево не публикуется никогда |

## Правила размещения

1. **Канон деталей продукта — в дереве проекта.** Всё, что нужно коллегам для
   работы и что специфично проекту, фиксируется в проектных скилах дерева.
2. **Общие принципы, не заточенные под один проект, — глобально.** Проектный
   скил при необходимости повторяет нужную часть самодостаточно (кратко) и не
   зависит от наличия глобальной базы.
3. **Персональное в дерево не попадает.** В проектных скилах доступы
   формулируются универсально («свой прокси», env-переменные, «личный способ
   входа — в глобальной базе владельца»).
4. **`related:` в проектных скилах ссылается только на скилы того же дерева.**
   Обратные ссылки из проекта в глобальные обзорные скилы не нужны.
   Упоминание глобального скила в тексте допустимо с пометкой
   «(глобальный, может отсутствовать)» и при самодостаточном изложении.
5. **В корневом AGENTS.md каждого проекта всегда есть раздел**, отделяющий
   проектную информацию от глобальной: таблица пар «скил в дереве ↔ глобальная
   копия» с направлениями канона и правилом «никакой персональщины».
   Образец — `AGENTS.md` рабочего дерева ROBRA.

## Три модели пар «проект ↔ глобально»

| Модель | Устройство | Когда применять | Примеры |
|---|---|---|---|
| **Канон-проект + указатель** | Полный скил в дереве; в глобальной базе — сжатый указатель (2–2,5 КБ: описание, ссылка на канон, пометка «дерево может переехать») | Знание живёт в продукте и больше нигде не нужно | clickhouse-etl, robra-overview, grafana-dashboard-ops |
| **Канон-глобальный + проектный указатель/копия** | Канон глобально; в дереве — указатель или автономная копия | Знание порождается вне проекта (личный инструментарий) | project-search ↔ tools (канон глобальный, в дереве — автономная scr-копия) |
| **Универсальная dual-полная** | Обе копии полные; канон обычно глобальный; синхронизация ручная в обе стороны, обе шапки содержат взаимные пометки | Знание нужно и проекту (автономность коллег), и вне проекта | ip-sockets-cpp-lite, prometheus-metrics |

Порядок перевода между моделями:

- появился второй потребитель у проектного знания → переводим в
  «универсальную dual-полную» или выносим общий принцип в глобальный
  `entity-*`/методику, а в проекте оставляем проектную часть;
- проект закрылся → канон остаётся в его дереве (история), глобальный
  указатель помечается «архив».
- `npp-core` (ROBRA): пока один потребитель — канон в дереве; при появлении
  проекта вне ROBRA перевести в универсальную модель.

## Чек-лист перед публикацией дерева проекта

- [ ] Все `related:` проектных скилов резолвятся внутри дерева.
- [ ] Grep личного: никаких путей чужих машин, логинов, токенов, джампов.
- [ ] В корневом AGENTS.md есть раздел разделения знаний и таблица пар.
- [ ] Глобальные указатели ссылаются на существующие проектные каноны.
- [ ] Каждый факт в проектных скилах актуален (битые пути/ссылки вычищены).

## Связь с соседними скилами

- `skills-management` — организация базы знаний в целом (структура каталога,
  стримы, сущности, index/log/lint); этот скил — частный, но сквозной раздел
  о границе «проект vs глобальное».
- `skills-tools` — инструменты индексации/поиска по базе.
- `project-search`, `session-search` — аналогичные инструменты в деревьях
  проектов (в ROBRA — проектные скилы).
