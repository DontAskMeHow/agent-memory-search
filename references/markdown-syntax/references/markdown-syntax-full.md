## Ядро (CommonMark + GFM) — подробности

- **Emphasis**: `*italic*`, `**bold**`, `***both***`. Не срабатывает внутри слова
  (`snake_case_names`, `2*3*4` остаются как есть). Экранирование: `\*asterisk\*`.
- **Разрыв строки по CommonMark**: два пробела в конце строки или `\` в конце.
  В Markpad эти формы работают, плюс одиночный перенос = разрыв (см. ниже).
- **Заголовки**: anchor создаётся на каждый. H1/H2 можно подчёркиванием `=` / `-`.
- **Списки**: `-` `*`, нумерованные `1.` / любые маркеры, `)` тоже работает
  (`7)` `8)` …). Loose (через пустую строку) vs tight. Вложенность отступом.
- **Task-lists**: `- [ ]` / `- [x]`, вложенные тоже кликабельны в Markpad
  (галка редактирует файл).
- **Цитаты**: `>` с вложенностью, могут содержать списки и код.
- **Alerts (GFM)**: `> [!NOTE]` `[!TIP]` `[!IMPORTANT]` `[!WARNING]` `[!CAUTION]`.
- **Код**: инлайн-код; фенсы ` ```lang ` или ` ~~~lang `; блок без языка — без
  подсветки. Подсветка — highlight.js. Индент-код (4 пробела) тоже работает.
- **Таблицы**: выравнивание `:---` / `:---:` / `---:`; длинные ячейки переносятся;
  инлайн-разметка внутри (`**bold**`, `code`, ссылки); pipe экранируется `\|`;
  пустая ячейка — два pipe `| 1 || 3 |`.
- **Thematic breaks**: `---`, `***`, `___` (3+ одинаковых).
- **Ссылки**: `[text](url)`, с title, bare URL, URL в скобках, `<angle>`-URL,
  reference-style `[text][id]` + `[id]: url "title"`. Якоря в этом документе:
  `[назад](#heading)`.
- **Сноски**: `[^ref]` и `^[inline]`; определение `[^ref]: ...` может быть в любом
  месте; несколько ссылок на одну сноску ок; многоабзацное определение — с
  отступом продолжения.

## Расширения Markpad (полный диапазон)

- **Одиночный перенос строки = разрыв строки.** Отличие от CommonMark/GitHub,
  где это пробел. Для согласованности с GitHub — пустая строка между абзацами.
- **`==выделение==`** — фон-выделение жёлтым.
- **`^[inline сноска]`** — сноска без метки, читается там же, где написана.
- **`++вставка++`** — вставленный текст.
- **Definition lists** — термин на строке, `: определение` на следующих строках;
  у термина может быть несколько определений.
- **Wikilinks** — `[[file#heading]]`, `[[file#heading|alias]]`, `[[#heading]]`
  (внутри документа). Ссылка без `#` — **намеренно** литерал (`[[Notes]]` — это
  ещё и синтаксис нумерации ссылок CommonMark).
- **Block-ids** — абзац, заканчивающийся `^demo-block`; ссылка `[[#^demo-block]]`.
- **Alerts сверх GitHub** — `[!INFO]`, `[!TODO]`, `[!FAQ]`, `[!QUESTION]`,
  `[!EXAMPLE]`; сворачиваемые `[!NOTE]+` (открыт по умолчанию) и `[!NOTE]-`
  (закрыт, клик по заголовку открывает).
- **Math (KaTeX)** — `$...$` инлайн, `$$...$$` display; многострочные окружения
  (`\begin{aligned}` и др.) сохраняют строки; `\$5` — экранированный доллар.
- **Mermaid** — ` ```mermaid `: flowchart, sequenceDiagram, pie, gantt и прочее.
- **YAML front matter** — `---` … `---` в шапке: показывается панелью,
  редактируется в ней (а не как текст).


## Мультимедиа и документы

- **Изображения**: `![alt](path)`, title в кавычках (hover), reference-style
  `![alt][id]` + `[id]: path "title"`. Эмбед Obsidian `![[image.png]]` тоже
  работает. Куда падает вставленный/перетащенный файл — настройка: имя папки
  создаётся рядом с документом, токен `${filename}` = имя файла без расширения
  (пишется как у Typora/SoloMD; расширяется в имя папки, `..` и абсолютные пути
  запрещены).
- **Видео**: `![caption](file.mp4)` → плеер с контролами; форматы `mp4`, `webm`,
  `ogg`, `mov`.
- **Аудио**: `![caption](file.mp3)` → плеер; форматы `mp3`, `wav`, `aac`, `flac`,
  `m4a`. HTML-атрибуты `width`/`height` переносятся в плеер.
- **YouTube**: ссылка **отдельным абзацем** → миниатюра-превью (открывается в
  браузере); `![caption](https://youtu.be/...)` так же. Внутри предложения —
  обычная ссылка (чтобы не ломать фразу).
- **Ссылки на другие документы**: `[x](other.md)` открывает файл в новой вкладке.
  Пути резолвятся относительно текущего документа: `other.md` (сосед),
  `sub/deep.md`, `../sibling.md`, `/abs/root.md`, `C:/win/abs.md`,
  `with%20space.md` (percent-encoding декодируется), `other.md#heading` (якорь).
  Захватываемые расширения: `.md` `.markdown` `.mdown` `.mkd` `.txt`. Всё остальное
  (`.pdf`, картинки, папки) — отдаётся системе. Не захватываются: URL со схемой
  (`https://…/x.md`) и protocol-relative (`//example.com/x.md`). Wikilink-форма
  `[[sub/deep#Setup]]` дописывает `.md` сама.

## Что Markpad сознательно НЕ рендерит (и почему)

| Синтаксис | Причина отказа |
|---|---|
| `~x~` subscript | GFM уже использует `~` для зачёркивания (1–2 тильды); `H~2~O` выглядел бы по-разному. Писать `H2O` |
| `^x^` superscript | два карета в одном абзаце спариваются: `a^2 + b^2 = c^2` сломалось бы |
| `\|\|spoiler\|\|` | совпадает с записью пустой ячейки таблицы (`| 1 \|\| 3 |` схлопнется) |
| `:emoji:` | не входит в ядро; на GitHub работает, в Markpad нет — использовать сам символ |

## Raw HTML

Разрешён и санитизируется. `<style>` — единственный тег, который вырезается
(чтобы документ не перестилизовывал приложение). Работают `<details>`/
`<summary>`, `<kbd>`, `<mark>`, `<sub>`, `<sup>`, `<table>` и др. Markdown
внутри HTML-блока продолжает рендериться. `<mark>`, `<sub>`, `<sup>` — способ
получить выделение/индексы там, где Markdown-синтаксиса нет.

## Поведенческие фичи (не синтаксис, а «бесплатно»)

- Клик по чекбоксу task-list в превью правит файл (`[ ]` → `[x]`).
- Hover по заголовку → якорь; правый клик → Copy Reference (стиль `[[…]]` или
  `[…](#…)` — как уже использует документ).
- Правый клик по абзацу/пункту/заголовку → Edit открывает редактор на этих строках.
- Сворачивание по заголовку (шеврон), помнится на документ.
- Связанная прокрутка split view — по исходной строке, не по соотношению.
- Копирование из превью сохраняет форматирование (в Word/Mail/Docs — как стили,
  в plain-text — как markdown).
- Sticky scroll заголовка; оглавление следует за прокруткой.
- Автодополнение заголовков при вводе `](#` и `[[#`.
- Экспорт в HTML / печать в PDF — математика и диаграммы включены.
