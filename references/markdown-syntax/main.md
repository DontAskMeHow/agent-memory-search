# Markdown: синтаксис и его подмножества

Один и тот же markdown-файл рендерится по-разному в зависимости от того, куда
он попадает. Правило поэтому не «как писать markdown», а «какое **подмножество**
синтаксиса выбрать под цель файла».

Полный каталог фич с совместимостью — `references/markdown-syntax-full.md`.
Здесь — правила выбора и краткий справочник по каждому таргету.

## Пять целей и матрица выбора

| Цель файла | Где смотрят | Что писать |
|---|---|---|
| **По умолчанию** (неизвестный вьюер) | что угодно | CommonMark + GFM-база — максимально переносимо |
| **Markpad** | личный десктоп-вьюер (`sftwrdotdev/Markpad`) | полный диапазон, включая расширения |
| **README.md** | GitHub / GitLab | GFM-подмножество (расширения Markpad не использовать) |
| **Confluence-статья** | конвертер → страница Confluence | стандартный md + GitHub Alerts + картинки |
| **План / ответ в чате** | терминал kimi-code / kimi-cli | лёгкое подмножество (см. оговорку) |

**Алгоритм выбора:**

1. Знаешь, что файл смотрит пользователь в Markpad → бери полный диапазон (секция «Markpad»).
2. Файл идёт в git-репозиторий (README и т.п.) → GFM-подмножество.
3. Файл — будущая Confluence-страница → подмножество «Confluence-статья».
4. Файл — план или ответ, который показывается в окне чата → лёгкое подмножество.
5. Не знаешь куда → «по умолчанию», без расширений.

Если файл может попасть в несколько мест одновременно (например, лежит в репо И
открывается в Markpad) — писать **по самому ограниченному** из таргетов.


## 1. По умолчанию (переносимое ядро)

Работает везде: в Markpad, на GitHub/GitLab, в терминале, при конвертации в
Confluence. Используй по умолчанию.

- Заголовки `#`–`######` (плюс подчёркивание `=` / `-` для H1/H2)
- `**bold**`, `*italic*`, `***both***`, `` `inline code` ``, `~~strikethrough~~`
- Списки `-` / `*` / `1.` / `1)`, вложенность, loose/tight
- Task-lists: `- [ ]` / `- [x]`
- Таблицы с выравниванием `:---`, `:---:`, `---:`; pipe в ячейке экранируется `\|`
- Цитаты `>`, вложенные цитаты
- Код-фенсы с языком ` ```python ` (или ` ~~~ `), индент-код (4 пробела)
- Ссылки `[text](url "title")`, reference-style, bare URL, `<angle>`-URL
- Сноски `[^ref]` + определение `[^ref]: ...`
- Тематические разделители `---` / `***` / `___`
- Экранирование через `\`, HTML-entities (`&copy;` `&mdash;` `&rarr;`)

Переносимое **правило абзацев**: между абзацами — пустая строка. Одиночный
перенос строки в CommonMark/GitHub трактуется как пробел (текст перетекает).
Разрыв строки по CommonMark — два пробела в конце строки или `\` в конце.


## 2. Markpad — полный диапазон

Личный просмотрщик пользователя. Вдобавок к ядру рендерит много расширений — **их и надо
использовать**, когда файл ориентирован на Markpad, чтобы не сводить документ
к базовому набору.

**Формальные расширения:**

- `==highlight==` — выделение жёлтым
- `^[inline сноска]` — сноска прямо в тексте, без метки
- `++inserted++` — вставленный текст (Pandoc/CriticMarkup)
- Definition lists — термин и `: определение` на следующих строках
- Wikilinks: `[[file#heading]]`, `[[file#heading|алиас]]`, `[[#heading]]`
- Эмбеды: `![[image.png]]` (Obsidian-стиль, локальный файл)
- Block-ids: абзац, оканчивающийся `^id`, ссылка `[[#^id]]`
- Alerts сверх GitHub: `[!INFO]`, `[!TODO]`, `[!FAQ]`, `[!QUESTION]`,
  `[!EXAMPLE]`; сворачиваемые `[!NOTE]+` (открыт) / `[!NOTE]-` (закрыт)
- Math: `$...$` инлайн, `$$...$$` display (KaTeX). Идентификаторы с `_`
  (`num_layers`) — **экранировать `\_`**, иначе KaTeX превратит `_layers` в
  нижний индекс; голый `_x` / `_{..}` — только для настоящих индексов.
  Цены-доллары в прозе — `\$5`. Корректный показ `\_` требует Markpad **≥ 2.7.4**
  (в 2.6.x парсер съедает экран до передачи в KaTeX — лечится обновлением).
- Mermaid: ` ```mermaid ` — flowchart/sequence/pie/gantt и прочее
- YAML front matter в шапке — показывается панелью, редактируется в ней

**Мультимедиа и документы:**

- YouTube-ссылка **отдельным абзацем** → превью-миниатюра; `![caption](url)` на
  YouTube делает то же. Внутри предложения — остаётся обычной ссылкой.
- `![](clip.mp4)` → видеоплеер (mp4, webm, ogg, mov); `![](sound.mp3)` →
  аудиоплеер (mp3, wav, aac, flac, m4a). `width`/`height` в HTML переносятся.
- `[текст](other.md)` → открывает файл в новой вкладке (относительные пути,
  расширения `.md` `.markdown` `.mdown` `.mkd` `.txt`; схемы `https://` и
  `//host` остаются внешними). `[[sub/deep#Setup]]` резолвится и дописывает `.md`.

**Отличие, влияющее на весь макет:**

- **Одиночный перенос строки = разрыв строки** (как в Obsidian/Typora), а не
  пробел. Аккуратнее переносить строки вручную: на GitHub это перетечёт в один
  абзац. Если документ должен одинаково выглядеть и в Markpad, и на GitHub —
  разделяй абзацы пустой строкой.

**Raw HTML:** разрешён и санитизируется; `<style>` вырезается. Работают
`<details>`/`<summary>`, `<kbd>`, `<mark>`, `<sub>`, `<sup>`, `<table>` и т.д.
Markdown внутри HTML-блока продолжает рендериться.

**Что Markpad сознательно НЕ рендерит** (не использовать, замена — справа):

| Синтаксис | Как воспринимается | Чем заменить |
|---|---|---|
| `~x~` | зачёркивание (GFM `~`) | `<sub>` или просто H2O |
| `^x^` | литерал | `<sup>` |
| `||spoiler||` | литерал (конфликт с пустой ячейкой `| 1 \|\| 3 |`) | `<details>` |
| `:emoji:` | литерал | сам символ emoji |


## 3. README.md в GitHub / GitLab

Целевой рендерер — GFM (GitHub Flavored Markdown), тот же у GitLab.

Разрешено (сверх ядра): `~~strikethrough~~`, task-lists, таблицы, сноски,
bare URL, GFM-alerts (`[!NOTE] [!TIP] [!IMPORTANT] [!WARNING] [!CAUTION]`).

**НЕ использовать** (станут литералом на GitHub/GitLab):

- `==highlight==`, `^[inline]`, `++inserted++`, definition lists
- wikilinks `[[...]]`, эмбеды `![[...]]`, block-ids `^id`
- одиночный перенос строки как разрыв (перетечёт в пробел)
- `:emoji:` — на **GitHub** работает, на **GitLab** нет; для кроссплатформы
  вставляй сам символ emoji
- raw-HTML — на GitHub ограничен (часть тегов вырезается), в README лучше им
  не злоупотреблять
- Mermaid — на GitHub/GitLab работает при ` ```mermaid `, но не во всех
  вьюерах; KaTeX только если включён

Признак README-таргета: файл лежит в git-репозитории, коммитится и читается
через веб-интерфейс хостинга.

## 4. Confluence-статья (через конвертер)

> Справочно: конвертер и скилы confluence-* — из исходной системы коллег,
> у нас не развёрнуты. Раздел оставлен как методика подмножества синтаксиса.

Файлы, которые потом конвертируются в страницы Confluence. Работает конвертер
`confluence-workflow/scripts/article_md2storage.py` в «статейном» стиле. Ключевой
принцип (см. скил `confluence-macros`): **md остаётся стандартным**, чтобы
читаться в любом вьюере, включая Markpad.

- Выноски — GitHub Alerts; тип маппится на карточку (`[!NOTE]/[!TIP]/[!INFO]/
  [!TODO]/[!EXAMPLE]` → синяя; `[!IMPORTANT]/[!WARNING]` → жёлтая;
  `[!CAUTION]/[!DANGER]` → красная; `[!SUCCESS]/[!DONE]` → зелёная). Заголовок
  выноски — на той же строке после `]`.
- Картинки — обычный `![Подпись](диаграмма.svg)` → figure (SVG вставляется
  содержимым); png/jpg → figure со ссылкой на вложение.
- Формулы — `$$ … $$` и `$ … $` (KaTeX-синтаксис; внутри — TeX-lite: `\frac`,
  `\sqrt`, индексы/степени, `\times`, `\text{…}`). Идентификаторы целиком —
  через `\_`, доллары-цены — `\$`. Полный канон — скил `confluence-macros`.
- Метаданные — секция `## Сведения о документе` в конце файла (таблица
  «Поле | Значение»); конвертер её вырезает и читает. Внутри полей не `|`.
- Глоссарий — заголовок со словом «словарь» + таблица «Термин | Что это | Пример».
- Секция `# Источники` — автоматически оформляется списком.
- **НЕ использовать**: fenced-div `::: card / gloss / svg` (устарело, Markpad не
  рендерит); YAML front matter в новых статьях (предпочитать секцию
  «Сведения о документе»).

## 5. План / ответ в чате kimi-code / kimi-cli

Когда агент пишет **план** (plan-файл) или развёрнутый ответ, который
показывается в окне чата — там работает **лёгкое терминальное подмножество**
(CommonMark + GFM-база), а не полный рендерер.

**Расширенный синтаксис здесь НЕ применять:**
Mermaid-диаграммы, KaTeX `$...$`, wikilinks/эмбеды `[[...]]` `![[...]]`,
block-ids, definition lists, `==highlight==`, `++insert++`, инлайн-сноски
`^[...]`, YouTube-превью, картинки/аудио/видео-плееры, front-matter-панель,
raw-HTML.

**Что использовать:** заголовки (вложенность мелкая), абзацы, `**bold**` /
`*italic*` / `` `code` ``, списки и task-lists, небольшие таблицы,
код-фенсы с языком, простые ссылки, цитаты. Таблицы держать небольшими
(узкий терминал ломает широкие).

Тот же `.md`-файл в чате и в Markpad выглядит по-разному: план-файлы/ответы
пишутся под терминал, а не под расширенный набор.
